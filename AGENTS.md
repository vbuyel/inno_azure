## Общее правило реализации

1. **Sync:** README.md должен соответствовать текущей реализации

## Правило реализации Mock (Mock Implementation Rule)

1. **Обязательная реализация mock:** При отсутствии активной подписки Azure, сетевого доступа к Azure API или при локальном тестировании инфраструктуры **необходимо реализовать и использовать mock-окружение**, полностью имитирующее жизненный цикл целевых облачных ресурсов.
2. **Terraform Mock:** Для локальной проверки сценариев Terraform (`init`, `plan`, `apply`, `output`, `destroy`) используется директория `infrastructure/environments/mock/`, построенная на встроенном ресурсе `terraform_data` (без обращения к реальному Azure API) с сохранением контракта ресурсов и outputs (`id`, `location`, `name`).
3. **Azure CLI Mock:** Для локальной проверки команд `az` (`group create`, `group show`, `group delete`, `account show`) используется скрипт `scripts/mock-az.sh`, эмулирующий ответы Azure CLI в JSON-формате и хранящий состояние локально.
4. **Прозрачность:** В отчётах и выводах всегда явно указывается, что операции выполнены в mock-режиме.
